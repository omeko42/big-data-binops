1. Gambaran Arsitektur & Lingkungan

API Portal Integrasi Keluar CAS (Computer Aided System / Big Data Binops) Bareskrim Polri dirancang untuk mendistribusikan data resmi Laporan Polisi (LP) kepada sistem mitra yang telah diverifikasi secara kedinasan. Antarmuka ini dirancang khusus dengan memperhatikan kepatuhan hukum, isolasi data, dan keamanan berlapis.

1.1 Spesifikasi Dasar Koneksi

Parameter Nilai / Keterangan
Base URL Produksi https://cas.bareskrim.polri.go.id/api/external/v1
Format Payload application/json; charset=utf-8
Metode Autentikasi HTTP Basic Authentication (Username + Password terenkripsi)
Scope Data Hanya mengekspos data berstatus OPERASIONAL. Data simulasi, uji coba sistem, atau data internal terisolasi secara ketat.
Enkripsi ID Objek ID record LP yang disajikan berupa token opaque terenkripsi (AES cipher token) untuk mencegah scraping dan pemetaan sekuensial.

2. Autentikasi & Keamanan Jaringan

Semua panggilan ke API wajib menyertakan header Authorization: Basic <credentials>, di mana <credentials> merupakan hasil enkoding Base64 dari pasangan <CLIENT_ID>:<CLIENT_SECRET>.

Distribusi Kredensial Resmi: Kredensial produksi (Client ID & Password) tidak dicantumkan pada dokumen teknis terbuka ini. Pasangan kredensial akan diserahkan secara langsung melalui saluran koordinasi resmi oleh pejabat/personel Bareskrim Polri yang berwenang.

2.1 Pengamanan IP Whitelist

Sistem menerapkan proteksi firewall berbasis IP Whitelist per klien. Mitra wajib mendaftarkan alamat IP publik (Static IP) server aplikasi / worker yang akan memanggil API ini.

Perhatian: Permintaan yang datang dari alamat IP yang belum didaftarkan akan otomatis ditolak dengan status HTTP 403 Forbidden dengan pesan "Akses ditolak: IP Anda tidak terdaftar dalam IP whitelist klien ini.".

2.2 Pembatasan Frekuensi (Rate Limiting)

Untuk menjaga stabilitas operasional server Bareskrim Polri, diberlakukan pembatasan laju panggilan (Rate Limit):

  • Batas Maksimal: 120 request per menit per Client ID.
  • Algoritma: Sliding-window in-memory per IP & Client.
  • Perilaku jika Melampaui Batas: Server mengembalikan respon HTTP 429 Too Many Requests. Sistem klien diharapkan mengimplementasikan mekanisme retry dengan pola exponential backoff.

3. Hak Akses & Granular Scope (9 Kategori Data)

Sistem Portal Integrasi Keluar menggunakan prinsip Least Privilege. Data yang dikembalikan pada respon JSON bersifat dinamis: hanya kolom/objek yang tercakup di dalam Scope yang disetujui yang akan disertakan dalam respons. Field di luar hak akses klien tidak akan dimunculkan sama sekali.

Kode Scope Klasifikasi Field yang Dikembalikan & Penjelasan
laporan_polisi.read Wajib (Dasar) Data Identitas LP:
id (token opaque), dors_lp_id, no_laporan, tgl_laporan, model_lp, status, updated_at.
laporan_polisi.klasifikasi Tindak Pidana Hierarki Hukum:
golongan_kejahatan (mis. Kejahatan Konvensional, Khusus, dll), jenis_kejahatan, tindak_pidana (array pasal yang disangkakan dan kategori tindak pidana).
laporan_polisi.status Status Perkara Progres & Crime Clearance:
status_code (kode tahapan riil), status_nama (nama tahapan riil), status_kategori (CC atau CT), is_selesai (boolean), tanggal_selesai, status_pelimpahan, keterangan_penghentian (objek putusan SP3, Restorative Justice, Diversi, atau penetapan PERMA Tipiring).
laporan_polisi.penanganan Penyidik Satker & Penyidik Penangan:
satker_penanganan (nama Satker/Polda/Polres), unit_penanganan (Subdit/Unit pemeriksa), personel_penanganan (array personel pembuat, penerima, dan mengetahui).
laporan_polisi.tkp Spasial & TKP Lokasi & Waktu Kejadian:
waktu_kejadian, tempat_kejadian, kategori_lokasi, hierarki wilayah: tkp_provinsi, tkp_kabupaten, tkp_kecamatan, tkp_desa, koordinat geospasial: lat, lon.
laporan_polisi.kronologi Naratif / Korpus Uraian Kejadian & Modus:
uraian_kejadian (deskripsi lengkap fakta peristiwa), apa_terjadi (peristiwa pidana yang dilaporkan), bagaimana_terjadi (kronologis/modus operandi). (Sangat penting untuk RAG / Semantic Search Gen AI).
laporan_polisi.kerugian Ekonomi Dampak Kerugian:
kerugian (nominal estimasi kerugian materiil korban).
laporan_polisi.pihak_terlibat Subjek Hukum Saksi, Korban, Terlapor:
pihak_terlibat: array nama, NIK (disamarkan/sesuai izin), peran keterlibatan (SAKSI, KORBAN, TERLAPOR/TERSANGKA).
laporan_polisi.barang_bukti Barang Bukti Objek Bukti:
barang_bukti: array jenis barang bukti, kuantitas/jumlah, status barang bukti, keterangan sita/aman.

4. Endpoint: Daftar & Pencarian Laporan Polisi

GET /api/external/v1/laporan-polisi

Mengambil daftar Laporan Polisi dengan paginasi, mendukung berbagai filter parameter yang sangat berguna untuk pipeline penyerapan data (*ETL / Data Ingestion*) ke dalam model Gen AI.

Parameter Query

Parameter Tipe Default Keterangan
page integer 1 Halaman yang diminta (dimulai dari 1).
limit integer 20 Jumlah data per halaman (maksimal 100).
no_laporan string - Pencarian nomor LP (pencarian parsial, case-insensitive). Contoh: LP/B/123/IX/2026.
status string - Filter tahapan riil penanganan perkara. Nilai acuan:
PENYELIDIKAN, PENYIDIKAN, SPDP, TAHAP_I, P21, TAHAP_II, SP3, SP2_LIDIK, PERMA.
status_kategori string - Filter kategori penyelesaian Crime Clearance:
• CC : Kasus telah tuntas / diselesaikan.
• CT : Kasus masih berproses (Laporan Polisi aktif).
satker string - Filter nama kesatuan kewilayahan atau unit pemeriksa (Contoh: METRO JAYA, POLRES KAMPAR, DITRESKRIMUM).
updated_from string (Date) - Format: YYYY-MM-DD. Mengambil LP yang diperbarui pada atau setelah tanggal ini. Kunci utama sinkronisasi incremental!
updated_to string (Date) - Format: YYYY-MM-DD. Mengambil LP yang diperbarui hingga batas tanggal ini.

6. Standar Status & Crime Clearance (CC / CT)

Pada sistem CAS / BDB, penyelesaian perkara pidana terbagi dalam dua kelompok indikator utama Polri:

  • Crime Total (CT): Kasus yang dilaporkan dan saat ini masih berada dalam tahapan penyelidikan / penyidikan aktif. (status_kategori = "CT", is_selesai = false).
  • Crime Clearance (CC): Kasus yang telah dinyatakan selesai penanganannya oleh Polri. (status_kategori = "CC", is_selesai = true).

Format Data Penghentian Perkara Khusus (Restorative Justice / SP3)

7. Respon & Error Handling

API mengembalikan kode status HTTP standar beserta format payload error terpadu:

Kode HTTP Penyebab Masalah Format Payload Error
200 OK Permintaan berhasil diproses. {"status": 1, "data": [...], "meta": {...}}
400 Bad Request Format parameter tidak valid (mis. tanggal bukan YYYY-MM-DD). {"status": 0, "statusCode": 400, "message": "updated_from harus format YYYY-MM-DD."}
401 Unauthorized Header Basic Auth tidak disertakan atau kredensial salah. {"status": 0, "statusCode": 401, "message": "Kredensial tidak dikenali."}
403 Forbidden IP klien belum di-whitelist atau akun klien berstatus non-aktif. {"status": 0, "statusCode": 403, "message": "Akses ditolak: IP Anda tidak terdaftar dalam IP whitelist klien ini."}
404 Not Found ID Laporan Polisi tidak ditemukan dalam database. {"status": 0, "statusCode": 404, "message": "Laporan Polisi tidak ditemukan."}
429 Rate Limited Melampaui kuota 120 request per menit. {"status": 0, "statusCode": 429, "message": "Terlalu banyak permintaan (rate limit terlampaui). Batas maksimal 120 request per menit."}

8. Panduan Khusus Integrasi Generative AI & RAG

💡 Rekomendasi Arsitektur untuk Tim AI / Data Engineer

Modul API ini dirancang untuk mendukung sistem berbasis Retrieval-Augmented Generation (RAG), klasifikasi hukum otomatis, dan analisis pola modus operandi kejahatan. Berikut adalah panduan penyerapan data yang efisien:

8.1 Strategi Sinkronisasi Bertahap (Incremental Sync Pattern)

Jangan melakukan crawling seluruh basis data secara berkala. Manfaatkan parameter updated_from untuk membangun ingestion pipeline yang efisien:

  1. Initial Hydration: Tarik data awal menggunakan paginasi (loop page=1..N dengan limit=100), berikan jeda/throttle 500ms antar-request agar tidak memicu Rate Limiter (120 req/menit).
  2. Incremental Pipeline (Cron / Worker): Jalankan worker setiap interval tertentu (misal tiap 10 menit atau 1 jam) dengan parameter updated_from = <timestamp_sinkronisasi_terakhir>.
  3. Update Vector Store: Jika record dengan id yang sama telah ada di Vector DB / Knowledge Base Anda, lakukan penimpaan (upsert) karena tahapan perkara mungkin telah berubah (misal dari PENYIDIKAN menjadi TAHAP_II atau SP3).

8.2 Strategi Chunking & Kontekstualisasi Teks Dokumen

Untuk menghasilkan pencarian semantik (*Vector Similarity*) yang akurat, disarankan menggabungkan teks narasi dengan konteks metadata sebelum di-embed: 

# Contoh Template Dokumen untuk Vector Embedding:
DOKUMEN KASUS:
- Nomor LP: {no_laporan}
- Tanggal: {tgl_laporan}
- Klasifikasi: {golongan_kejahatan} / {jenis_kejahatan}
- Pasal: {tindak_pidana.pasal}
- Satker Penangan: {satker_penanganan}
- Status Perkara: {status_nama} ({status_kategori})
- TKP: {tempat_kejadian}, {tkp_kecamatan}, {tkp_kabupaten}, {tkp_provinsi}

URAIAN MODUS DAN PERISTIWA:
{apa_terjadi}
{bagaimana_terjadi}
{uraian_kejadian}

8.3 Kepatuhan Privasi Data (UU PDP & Keamanan Dokumen Polri)

Perhatian Privasi Data (Data Privacy Guardrails): Data Laporan Polisi memuat informasi sensitif. Sesuai prinsip UU No. 27 Tahun 2022 tentang Perlindungan Data Pribadi (UU PDP):
  • Lakukan sanitasi / penyensoran otomatis (*Masking / Redaction*) terhadap NIK dan nama korban sebelum diumpankan ke LLM pihak ketiga jika menggunakan Cloud Model.
  • Sangat direkomendasikan menjalankan model LLM secara On-Premise / Private Deployment untuk menjaga kerahasiaan materi penyelidikan Polri.

9.2 Python (Worker / ETL Ingestion Pipeline)

import requests
import time
from requests.auth import HTTPBasicAuth

BASE_URL = "https://cas.bareskrim.polri.go.id/api/external/v1"
CLIENT_ID = "<CLIENT_ID>"          # Disediakan resmi oleh Bareskrim
CLIENT_SECRET = "<CLIENT_SECRET>"  # Disediakan resmi oleh Bareskrim

auth = HTTPBasicAuth(CLIENT_ID, CLIENT_SECRET)

def fetch_laporan_polisi(updated_from=None, page=1, limit=50):
    params = {
        "page": page,
        "limit": limit
    }
    if updated_from:
        params["updated_from"] = updated_from

    response = requests.get(
        f"{BASE_URL}/laporan-polisi",
        params=params,
        auth=auth,
        headers={"Accept": "application/json"},
        timeout=15
    )

    if response.status_code == 200:
        return response.json()
    elif response.status_code == 429:
        print("Rate limit terlampaui, menunggu 5 detik...")
        time.sleep(5)
        return fetch_laporan_polisi(updated_from, page, limit)
    else:
        raise Exception(f"Gagal mengambil data: HTTP {response.status_code} - {response.text}")

# Contoh pemanggilan:
if __name__ == "__main__":
    result = fetch_laporan_polisi(updated_from="2026-09-01")
    print(f"Total data ditemukan: {result['meta']['total']}")
    for lp in result["data"]:
        print(f"[{lp['no_laporan']}] - {lp.get('status_nama')} - {lp.get('jenis_kejahatan')}")

9.3 Node.js / TypeScript

import axios from 'axios';

const BASE_URL = 'https://cas.bareskrim.polri.go.id/api/external/v1';
const CLIENT_ID = '<CLIENT_ID>';
const CLIENT_SECRET = '<CLIENT_SECRET>';

async function getLaporanPolisi(page = 1, limit = 50) {
  try {
    const authHeader = 'Basic ' + Buffer.from(`${CLIENT_ID}:${CLIENT_SECRET}`).toString('base64');
    
    const response = await axios.get(`${BASE_URL}/laporan-polisi`, {
      params: { page, limit },
      headers: {
        'Authorization': authHeader,
        'Accept': 'application/json'
      },
      timeout: 10000
    });

    return response.data;
  } catch (error: any) {
    if (error.response?.status === 429) {
      console.warn('Rate limit exceeded. Silakan kurangi frekuensi request.');
    }
    throw error;
  }
}
