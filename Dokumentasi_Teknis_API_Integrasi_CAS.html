1. Gambaran Arsitektur & Lingkungan

API Portal Integrasi Keluar CAS (Crime Analytic System) / BDB (Big Data Binops) Bareskrim Polri dirancang untuk mendistribusikan data resmi Laporan Polisi (LP) secara aman dan terstruktur kepada sistem mitra yang telah diverifikasi (Kementerian/Lembaga, dashboard analitik, platform operasional, maupun sistem pengolahan data cerdas).

Antarmuka ini beroperasi sebagai pintu gerbang (*Managed Integration Gateway*) yang mengedepankan isolasi data operasional, kontrol hak akses granular (*Scope*), pembatasan frekuensi (*Rate Limiting*), serta pengamanan lalu lintas berbasis *IP Whitelisting*.

1.1 Spesifikasi Dasar Koneksi

Parameter Nilai / Keterangan
Base URL Produksi https://cas.bareskrim.polri.go.id/api/external/v1
Format Payload application/json; charset=utf-8
Metode Autentikasi HTTP Basic Authentication (Username / Client ID + Password terenkripsi)
Scope Data Hanya mengekspos data berstatus OPERASIONAL. Data simulasi, uji coba sistem, atau data internal terisolasi secara ketat.
Enkripsi ID Objek ID record LP yang disajikan berupa token opaque terenkripsi (AES cipher token) untuk mencegah scraping dan pemetaan sekuensial.

1.2 Sumber Data & Integrasi DORS (Daily Operation Report System)

Terintegrasi Langsung dengan DORS Mabes Polri: Seluruh data Laporan Polisi (LP) yang didistribusikan melalui antarmuka CAS/BDB ini bersumber langsung dan tersinkronisasi secara berkesinambungan dengan sistem DORS (Daily Operation Report System) Mabes Polri.

DORS merupakan sistem pelaporan operasi harian resmi di mana seluruh Sentra Pelayanan Kepolisian Terpadu (SPKT) dan satuan fungsi reserse di tingkat Mabes Polri, Polda, Polres, hingga Polsek di seluruh Indonesia menginput data Laporan Polisi awal.

Melalui platform CAS (Crime Analytic System) / BDB (Big Data Binops), data mentah dari DORS telah melalui proses:

  • Standardisasi & Pembersihan Data: Penyelarasan format nomor laporan, penyeragaman penulisan pasal, dan verifikasi kelengkapan identitas LP.
  • Pemetaan Hierarki Satker: Penataan struktur satuan kerja penangan perkara secara akurat dari tingkat Mabes hingga Polsek jajaran.
  • Penelusuran Crime Clearance (CC): Pelacakan tahapan tindak lanjut perkara (Lidik, Sidik, SPDP, Tahap I, P21, Tahap II, SP3/Restorative Justice, hingga penetapan sidang PERMA Tipiring).
  • Interoperabilitas dengan Field dors_lp_id: Setiap record tetap membawa ID asli sistem DORS (dors_lp_id) untuk menjamin kemudahan rekonsiliasi (*cross-referencing*) dengan sistem internal kepolisian lainnya.

2. Autentikasi & Keamanan Jaringan

Setiap permintaan ke API wajib menyertakan header Authorization: Basic <credentials>, di mana <credentials> merupakan hasil enkoding Base64 dari format <CLIENT_ID>:<CLIENT_SECRET>.

Distribusi Kredensial Resmi: Kredensial produksi (Client ID & Password) tidak dicantumkan pada dokumen panduan teknis umum ini. Pasangan kredensial akan diserahkan secara resmi dan terpisah melalui jalur kedinasan Bareskrim Polri oleh pejabat/personel yang berwenang.

2.1 Pengamanan IP Whitelist (Wajib)

Sistem menerapkan proteksi firewall berbasis IP Whitelist per klien. Tim pengembang mitra wajib mendaftarkan alamat IP publik statis (*Static Public IP*) dari server backend atau data worker yang akan mengakses API.

Perhatian: Permintaan yang datang dari alamat IP di luar daftar whitelist akan otomatis ditolak oleh server dengan status HTTP 403 Forbidden dengan pesan: "Akses ditolak: IP Anda tidak terdaftar dalam IP whitelist klien ini."

2.2 Pembatasan Frekuensi Permintaan (Rate Limiting)

Untuk menjaga keandalan dan stabilitas layanan server Bareskrim Polri, diberlakukan pembatasan frekuensi panggilan:

  • Batas Maksimal: 120 request per menit per Client ID.
  • Algoritma: Sliding-window in-memory per IP & Client.
  • Perilaku jika Melampaui Batas: Server mengembalikan status HTTP 429 Too Many Requests. Sistem pemanggil diharapkan menerapkan mekanisme *throttling* atau *retry* dengan jeda *exponential backoff*.

3. Hak Akses & Granular Scope (9 Kategori Data)

Sistem Portal Integrasi Keluar menerapkan prinsip *Least Privilege*. Data yang dikembalikan pada respon JSON bersifat dinamis: hanya field/objek yang tercakup di dalam Scope yang disetujui untuk klien yang akan disertakan dalam respon. Kolom di luar hak akses tidak akan dimunculkan dalam payload.

Kode Scope Klasifikasi Field yang Dikembalikan & Penjelasan
laporan_polisi.read Wajib (Dasar) Data Identitas Dasar LP:
id (token opaque), dors_lp_id, no_laporan, tgl_laporan, model_lp, status, updated_at.
laporan_polisi.klasifikasi Tindak Pidana Hierarki & Jenis Pidana:
golongan_kejahatan (mis. Kejahatan Konvensional, Transnasional, dll), jenis_kejahatan, tindak_pidana (array pasal dan kategori tindak pidana).
laporan_polisi.status Status Perkara Tahapan & Crime Clearance:
status_code (kode tahapan riil), status_nama (nama tahapan riil), status_kategori (CC atau CT), is_selesai (boolean), tanggal_selesai, status_pelimpahan, keterangan_penghentian (objek SP3, Restorative Justice, Diversi, atau PERMA Tipiring).
laporan_polisi.penanganan Penyidik Satker & Personel Penangan:
satker_penanganan (Polda / Polres / Polsek), unit_penanganan (Subdit / Unit pemeriksa), personel_penanganan (personel pembuat, penerima, dan mengetahui).
laporan_polisi.tkp Spasial & TKP Waktu & Lokasi Kejadian:
waktu_kejadian, tempat_kejadian, kategori_lokasi, hierarki administratif: tkp_provinsi, tkp_kabupaten, tkp_kecamatan, tkp_desa, titik koordinat: lat, lon.
laporan_polisi.kronologi Naratif / Modus Uraian Peristiwa & Modus Operandi:
uraian_kejadian (deskripsi lengkap fakta kejadian), apa_terjadi (peristiwa pidana yang dilaporkan), bagaimana_terjadi (kronologis modus operandi peristiwa).
laporan_polisi.kerugian Kerugian Dampak Kerugian:
kerugian (estimasi nilai kerugian materiil korban).
laporan_polisi.pihak_terlibat Subjek Hukum Pihak Terkait Kasus:
pihak_terlibat: array nama, NIK (disamarkan/sesuai regulasi), peran keterlibatan (SAKSI, KORBAN, TERLAPOR/TERSANGKA).
laporan_polisi.barang_bukti Barang Bukti Objek Barang Bukti:
barang_bukti: array jenis barang bukti, kuantitas/jumlah, status barang bukti, keterangan sita/aman.

4. Endpoint: Daftar & Pencarian Laporan Polisi

GET /api/external/v1/laporan-polisi

Mengambil daftar Laporan Polisi dengan paginasi, mendukung berbagai filter parameter untuk pencarian spesifik maupun sinkronisasi data bertahap (*Incremental ETL*).

Parameter Query

Parameter Tipe Default Keterangan
page integer 1 Nomor halaman yang diminta (dimulai dari 1).
limit integer 20 Jumlah baris per halaman (maksimal 100).
no_laporan string - Pencarian nomor LP (pencarian parsial, case-insensitive). Contoh: LP/B/241/IX/2026.
status string - Filter kode tahapan riil perkara:
PENYELIDIKAN, PENYIDIKAN, SPDP, TAHAP_I, P21, TAHAP_II, SP3, SP2_LIDIK, PERMA.
status_kategori string - Filter kategori penyelesaian Crime Clearance:
• CC : Crime Clearance (Perkara telah selesai diselesaikan).
• CT : Crime Total (Perkara masih berproses / aktif).
satker string - Filter nama Satker kewilayahan atau unit pemeriksa (Contoh: METRO JAYA, POLRES KAMPAR, DITRESKRIMUM).
updated_from string (Date) - Format: YYYY-MM-DD. Mengambil LP yang diperbarui pada atau setelah tanggal ini. Sangat direkomendasikan untuk sinkronisasi data berkala.
updated_to string (Date) - Format: YYYY-MM-DD. Mengambil LP yang diperbarui hingga batas tanggal ini.

6. Standar Status & Crime Clearance (CC / CT)

Dalam pelaporan kinerja penegakan hukum Polri, status perkara dikelompokkan ke dalam dua indikator utama:

  • Crime Total (CT): Seluruh Laporan Polisi yang diterima dan saat ini berada dalam tahapan penyelidikan maupun penyidikan aktif. (status_kategori = "CT", is_selesai = false).
  • Crime Clearance (CC): Laporan Polisi yang telah tuntas diselesaikan oleh Polri. (status_kategori = "CC", is_selesai = true). Jalur penyelesaian meliputi: penyerahan tersangka ke Kejaksaan (Tahap II / P21), penghentian penyidikan (SP3 / Restorative Justice / Diversi), atau penetapan putusan pengadilan cepat (PERMA Tipiring).

Format Data Penghentian Perkara Khusus (Restorative Justice / SP3)

Bila suatu perkara diselesaikan melalui jalur Restorative Justice (RJ) atau SP3, kolom keterangan_penghentian menyajikan rincian dokumen ketetapan:

7. Respon & Error Handling

API mengembalikan kode status HTTP standar beserta format payload JSON error yang terstruktur:

Kode HTTP Penyebab Masalah Format Payload Error
200 OK Permintaan berhasil diproses. {"status": 1, "data": [...], "meta": {...}}
400 Bad Request Format parameter tidak valid (mis. format tanggal bukan YYYY-MM-DD). {"status": 0, "statusCode": 400, "message": "updated_from harus format YYYY-MM-DD."}
401 Unauthorized Header Basic Auth tidak disertakan atau kredensial salah. {"status": 0, "statusCode": 401, "message": "Kredensial tidak dikenali."}
403 Forbidden IP klien belum di-whitelist atau akun klien berstatus non-aktif. {"status": 0, "statusCode": 403, "message": "Akses ditolak: IP Anda tidak terdaftar dalam IP whitelist klien ini."}
404 Not Found ID Laporan Polisi tidak ditemukan dalam database. {"status": 0, "statusCode": 404, "message": "Laporan Polisi tidak ditemukan."}
429 Rate Limited Melampaui kuota 120 request per menit. {"status": 0, "statusCode": 429, "message": "Terlalu banyak permintaan (rate limit terlampaui). Batas maksimal 120 request per menit."}

8. Praktik Terbaik Integrasi (Best Practices)

💡 Panduan Efisiensi & Ketahanan Sistem Pemanggil

Untuk memastikan pertukaran data berjalan optimal, efisien, dan tidak membebani infrastruktur kedua belah pihak, tim pengembang disarankan menerapkan pedoman berikut:

8.1 Pola Sinkronisasi Bertahap (Incremental Sync Pattern)

Hindari melakukan penarikan ulang (*crawling full database*) secara rutin. Gunakan parameter updated_from untuk sinkronisasi data yang efisien:

  1. Penarikan Awal (Initial Load): Tarik data awal menggunakan paginasi (loop page=1..N dengan limit=50 atau 100), berikan jeda/throttle minimum 500ms antar-request agar aman dari limit 120 req/menit.
  2. Sinkronisasi Rutin (Cron / Worker): Jalankan worker berkala (misal tiap 10–30 menit) dengan parameter: GET /laporan-polisi?updated_from=<timestamp_sinkronisasi_terakhir>.
  3. Operasi Upsert: Lakukan penyimpanan berbasis upsert (insert jika baru, update jika sudah ada) menggunakan kunci id atau no_laporan, karena tahapan penanganan perkara dinamis dan dapat berubah status (misal dari Sidik ke P21 atau SP3).

8.2 Pemanfaatan Lanjutan (Analitik, Geospasial, & Machine Learning / AI)

Data yang disediakan dapat dimanfaatkan untuk berbagai kebutuhan strategis:

  • Dashboard Analitik & Tren Kriminalitas: Mengagregasikan angka kejahatan per wilayah satker, kelompok jenis pidana, dan rasio penyelesaian perkara (*Crime Clearance Rate*).
  • Pemetaan Geospasial: Memetakan sebaran titik rawan kejahatan (*Crime Mapping*) memanfaatkan koordinat lat, lon, dan hierarki wilayah TKP.
  • Analitik Cerdas & Model AI: Memanfaatkan field naratif uraian_kejadian, apa_terjadi, dan bagaimana_terjadi sebagai bahan analisis pola modus operandi, pencarian kemiripan kasus (*similarity search / RAG*), maupun klasifikasi pasal otomatis.

8.3 Kepatuhan Privasi Data & Kerahasiaan Dokumen Polri

Perhatian Privasi Data (Data Privacy Guardrails): Informasi Laporan Polisi memuat data subjek hukum yang dilindungi oleh UU No. 27 Tahun 2022 tentang Perlindungan Data Pribadi (UU PDP):
  • Sistem mitra wajib menjamin keamanan penyimpanan data dan membatasi akses personel internal sesuai prinsip kerahasiaan kepolisian.
  • Bila data diolah menggunakan sistem analitik pihak ketiga atau cloud eksternal, lakukan proses penyamaran otomatis (*Masking / Redaction*) terhadap NIK dan identitas personal.

9.2 Python (Worker / ETL Script)

import requests
import time
from requests.auth import HTTPBasicAuth

BASE_URL = "https://cas.bareskrim.polri.go.id/api/external/v1"
CLIENT_ID = "<CLIENT_ID>"          # Diterbitkan resmi oleh Bareskrim
CLIENT_SECRET = "<CLIENT_SECRET>"  # Diterbitkan resmi oleh Bareskrim

auth = HTTPBasicAuth(CLIENT_ID, CLIENT_SECRET)

def fetch_laporan_polisi(updated_from=None, page=1, limit=50):
    params = {
        "page": page,
        "limit": limit
    }
    if updated_from:
        params["updated_from"] = updated_from

    response = requests.get(
        f"{BASE_URL}/laporan-polisi",
        params=params,
        auth=auth,
        headers={"Accept": "application/json"},
        timeout=15
    )

    if response.status_code == 200:
        return response.json()
    elif response.status_code == 429:
        print("Rate limit 120 req/menit terlampaui. Menunggu jeda 5 detik...")
        time.sleep(5)
        return fetch_laporan_polisi(updated_from, page, limit)
    else:
        raise Exception(f"Gagal mengambil data: HTTP {response.status_code} - {response.text}")

if __name__ == "__main__":
    result = fetch_laporan_polisi(updated_from="2026-09-01")
    print(f"Total data ditemukan: {result['meta']['total']}")
    for lp in result["data"]:
        print(f"[{lp['no_laporan']}] {lp.get('status_nama')} - {lp.get('jenis_kejahatan')}")

9.3 Node.js / TypeScript

import axios from 'axios';

const BASE_URL = 'https://cas.bareskrim.polri.go.id/api/external/v1';
const CLIENT_ID = '<CLIENT_ID>';
const CLIENT_SECRET = '<CLIENT_SECRET>';

async function getLaporanPolisi(page = 1, limit = 50, updatedFrom?: string) {
  try {
    const authHeader = 'Basic ' + Buffer.from(`${CLIENT_ID}:${CLIENT_SECRET}`).toString('base64');
    
    const response = await axios.get(`${BASE_URL}/laporan-polisi`, {
      params: { page, limit, updated_from: updatedFrom },
      headers: {
        'Authorization': authHeader,
        'Accept': 'application/json'
      },
      timeout: 10000
    });

    return response.data;
  } catch (error: any) {
    if (error.response?.status === 429) {
      console.warn('Rate limit exceeded (maksimal 120 request per menit).');
    }
    throw error;
  }
}

10. Prosedur Permohonan & Koordinasi Teknis

Tahapan pelaksanaan integrasi teknis mencakup:

  1. Pendaftaran IP Whitelist: Tim teknis mitra menyiapkan dan menyerahkan daftar alamat IP publik statis (*Static Public IP*) server yang akan digunakan untuk mengakses API kepada pihak Bareskrim Polri.
  2. Penetapan Hak Akses (Scope): Pemberian hak akses scope disesuaikan dengan mandat perjanjian kerjasama dan kebutuhan teknis sistem mitra.
  3. Penyerahan Kredensial Produksi: Pasangan Client ID dan API Secret Password akan diserahkan secara aman melalui koordinasi resmi kedinasan.
